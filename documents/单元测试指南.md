# 单元测试模块建设指南

本文档详细记录了 Bee-Plus 组件库单元测试模块的搭建过程、工具选择原因、配置方法以及常见问题解决方案。

## 1. 为什么选择 Vitest？

在 Bee-Plus 项目中，我们选择了 **Vitest** 作为单元测试框架。主要基于以下考量：

1.  **与 Vite 的原生集成**：
    *   Bee-Plus 是基于 Vite 构建的。Vitest 能够直接复用 Vite 的配置（如 `vite.config.ts` 中的插件、别名等），无需像 Jest 那样进行复杂的重复配置。
    *   这意味着我们可以在测试中直接处理 `.vue` 文件、TypeScript 和 ESM，开箱即用。

2.  **极速的执行效率**：
    *   Vitest 利用 Vite 的热更新（HMR）技术，只重新运行受更改影响的测试文件，在开发模式下反馈极快。
    *   它使用 Worker 线程并发运行测试，显著提高了 CI/CD 环境下的运行速度。

3.  **兼容 Jest API**：
    *   Vitest 的 API 设计（`describe`, `it`, `expect` 等）与 Jest 高度兼容。这意味着对于熟悉 Jest 的开发者来说，几乎没有学习成本。

## 2. 模块搭建与配置

### 2.1 依赖安装
我们在项目根目录安装了以下核心依赖：
```bash
npm install -D vitest @vue/test-utils jsdom
```
*   `vitest`: 测试运行器。
*   `@vue/test-utils`: Vue 官方的组件测试工具库，用于挂载和操作 Vue 组件。
*   `jsdom`: 在 Node.js 环境中模拟浏览器 DOM 环境（Vitest 默认不带 DOM 环境）。

### 2.2 配置文件：vitest.config.mts
我们在根目录创建了 `vitest.config.mts`，配置了 Vue 插件和 jsdom 环境：

```typescript
import { defineConfig } from 'vitest/config'
import vue from '@vitejs/plugin-vue'
import vueJsx from '@vitejs/plugin-vue-jsx'

export default defineConfig({
  plugins: [vue(), vueJsx()],
  test: {
    environment: 'jsdom', // 模拟浏览器环境
    globals: true,        // 允许直接使用 describe, it 等全局变量
    include: ['packages/**/*.{test,spec}.{js,mjs,cjs,ts,mts,cts,jsx,tsx}'] // 指定测试文件位置
  }
})
```

### 2.3 TypeScript 配置：tsconfig.vitest.json
为了避免测试文件影响主项目的类型检查，我们创建了专门的 `tsconfig.vitest.json`：

```json
{
    "extends": "./tsconfig.app.json",
    "compilerOptions": {
        "composite": true,
        "types": ["node", "jsdom", "vitest"]
    },
    // 关键：必须同时包含测试文件和源码文件
    "include": [
        "packages/components/**/__tests__/*",
        "packages/components/**/*.ts",
        "packages/components/**/*.tsx",
        "packages/components/**/*.vue"
    ]
}
```

## 3. 遇到的问题与解决方案

### 问题：TS 报错 "File ... is not in the file list of project"
**现象**：
在编写测试文件 `progress.test.ts` 时，IDE 报错提示引入的 `../src/progress.vue` 不在 `tsconfig.vitest.json` 的文件列表中。

**原因**：
TypeScript 的 `composite` 项目（多项目引用结构）要求非常严格。`tsconfig.vitest.json` 最初只 `include` 了 `__tests__` 目录下的文件。当测试文件引用了外部的源码文件（如 `src/progress.vue`）时，TypeScript 发现该源码文件不在当前“测试项目”的定义范围内，因此拒绝编译引用。

**解决**：
我们修改了 `tsconfig.vitest.json` 的 `include` 字段，显式地将组件的源码文件（`.ts`, `.tsx`, `.vue`）也包含进来。这样，在测试上下文中，源码文件也被视为该项目的一部分，从而修复了引用错误。

```json
"include": [
    "packages/components/**/__tests__/*",
    "packages/components/**/*.ts",  // 新增
    "packages/components/**/*.tsx", // 新增
    "packages/components/**/*.vue"  // 新增
]
```

## 4. 如何创建与运行测试

### 4.1 创建测试文件
在组件目录下新建 `__tests__` 文件夹，并创建 `[component-name].test.ts`。
例如 `packages/components/progress/__tests__/progress.test.ts`：

```typescript
import { describe, it, expect } from 'vitest'
import { mount } from '@vue/test-utils'
import BeeProgress from '../src/progress.vue'

describe('BeeProgress', () => {
    it('renders correctly', () => {
        const wrapper = mount(BeeProgress, {
            props: { percentage: 50 }
        })
        expect(wrapper.text()).toContain('50%')
    })
})
```

### 4.2 运行测试
在终端运行以下命令：

```bash
npm run test
```

### 4.3 测试结果解读
运行成功后，终端会显示如下绿色输出：

```text

      Tests  8 passed (8)  <-- 总共执行了 8 个具体的测试用例，全部通过
   Start at  14:43:18

```

*   **Test Files**: 显示有多少个文件被执行以及通过及情况。
*   **Tests**: 显示具体的测试用例（`it` 或 `test` 块）总数及通过数。
*   **绿色对勾 (✓)**: 表示该文件或用例通过测试。
